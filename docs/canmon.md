# CAN Monitor (Linux 노트북 + PCAN-USB Pro FD)

`qa canmon …` 명령과 QA Tools 창의 "CAN Monitor" 화면에 대한 설명입니다. 명령은 저장소 폴더에서 `./qa`로, 설치했다면 `qa`로 실행합니다.

화면별 사용법은 번호를 붙인 화면 이미지와 함께 [manual.html](manual.html)에 정리했습니다. 화면 이미지는 `python3 docs/make_shots.py`로 다시 만듭니다(`.deps`를 쓰는 PC에서는 앞에 `PYTHONPATH=.deps`).

## 준비

1. 노트북에 Ubuntu 등 Linux를 설치합니다. PCAN 드라이버(`peak_usb`)는 커널에 들어 있습니다.
2. 저장소를 받고 패키지를 설치합니다(저장소 README의 "설치"). 캡처(`qa canmon capture`)만 쓸 때는 추가 패키지가 필요 없습니다.
3. DBC는 저장소의 `data/dbc/`에 들어 있습니다. 다른 폴더의 DBC를 쓰려면 `CANMON_DBC_DIR` 환경변수로 지정합니다.
4. 분석기를 꽂고 `ip link`로 `can0`, `can1`이 보이는지 확인합니다.

## 로봇에 연결하기 전

- **변환 케이블:** HETC 5핀 커넥터를 D-Sub 9핀에 연결합니다. D-Sub는 2번이 CAN-L, 3번이 GND, 7번이 CAN-H입니다. 5V와 ESTOP 핀은 연결하지 않습니다. HETC 쪽 핀 배열은 멀티미터로 먼저 확인합니다.
- **종단:** 분석기 쪽 종단저항은 꺼 둡니다.
- **저항 확인:** 연결 전후로 CAN-H와 CAN-L 사이가 약 60 Ω인지 확인합니다.
- **연결 시점:** 로봇이 정지 상태일 때 연결합니다.

## 사용

```bash
# 1. 채널 설정. listen-only라 로봇 버스에 아무것도 보내지 않는다
sudo ./qa canmon setup can0 local     # 로컬 CAN 1 Mbps / 5 Mbps
sudo ./qa canmon setup can1 local     # D-CAN이면 dcan

# 2. 캡처 (Ctrl+C로 종료하거나 --seconds 지정)
./qa canmon capture can0 can1 -o ltact.csv --seconds 60

# 3. 주기 분석 보고서
./qa canmon analyze ltact.csv --map can0=HETC-L-TACT_ch0 --map can1=HETC-L-TACT_ch1 -o ltact.md

# 4. 특정 메시지의 신호를 CSV로 내보내기 (예: 손바닥 HTAC 엔코더)
./qa canmon analyze ltact.csv --map can1=HETC-L-TACT_ch1 --decode 0xF13382 -o enc51.csv
```

## 보고서에 나오는 것

- **메시지별 통계:** CAN ID별(STATUS·CTRL은 SubCode별, 촉각은 프레임별) 수신 수, 주기, 간격 최소·평균·p99·최대를 보여 줍니다.
- **설계 주기 비교:** 최대 간격이 설계 주기의 5배를 넘으면 표시합니다. 기준은 `--limit`으로 바꿉니다.
- **그 외:** 관찰된 프레임 길이 분포, DBC에 없는 ID, 오류 프레임 수, 추정 버스 부하를 함께 보여 줍니다.

## 확인되지 않은 것

- **타임스탬프 종류:** 하드웨어 타임스탬프가 실제로 들어오는지는 장비로 확인해야 합니다. 캡처가 끝나면 "hardware timestamps" 또는 "software timestamps only"가 표시됩니다. 소프트웨어 타임스탬프에는 USB와 스케줄링 지연이 섞이므로, 1 ms 미만의 간격 차이는 믿기 어렵습니다.
- **D-CAN 샘플 포인트:** 확인하지 못해 기본값을 씁니다.
- **실장비 검증:** `check_tools.py`로 파서와 분석기만 오프라인 검사했습니다. 실제 장비로 캡처해 본 적은 없습니다.

## 오프라인 뷰어 (1단계)

캡처 CSV를 열어 Trace, 주기 통계, 그래프로 보는 PyQt6 프로그램입니다. 로봇이나 분석기 없이 동작합니다.

```bash
./qa canmon sample sample_ltact.csv        # 가상 데이터 만들기
./qa gui canmon sample_ltact.csv --map can0=HETC-L-TACT_ch0 --map can1=HETC-L-TACT_ch1
```

- `sample_ltact.csv`는 `qa canmon sample`로 만든 **가상 데이터**입니다. 로봇에서 기록한 것이 아닙니다. can0의 `HTAC_61` 엔코더가 8.2초에 약 12 ms 끊기도록 넣어 두었습니다.
- 필요한 패키지는 `PyQt6`, `pyqtgraph`, `numpy`, `cantools`입니다. `pip install -e ".[gui]"`로 한 번에 설치됩니다.
- Windows에서도 Python과 위 패키지를 설치하면 `qa gui canmon 파일.csv`로 실행됩니다(확인하지는 못했습니다).
- 채널별 DBC는 왼쪽 "채널과 DBC"에서 고릅니다. 마지막 선택은 저장됩니다.

| 화면 | 기능 |
|---|---|
| Trace | ID별 고정(재생 시각의 최신 프레임, 펼치면 신호 값)과 시간순(전체 프레임, 필터, 선택하면 신호 값) |
| 주기 통계 | 메시지별 수신 수, 평균·최소·최대·p99, 설계 주기 대비, 한계 초과 강조. 범위는 측정 전체, 커서 A–B, 저장한 구간. 분포 그래프, CSV 내보내기 |
| 그래프 | 신호 값, 상태 신호, 수신 간격을 한 시간축에 표시. 커서 A·B, 샘플 점(확대 시), 직선·계단, 점에 마우스를 올리면 값과 간격 표시, 구간 저장, CSV·이미지 내보내기 |
| 위 도구 줄 | 파일 열기, 재생·일시정지, 배속, 시각 이동 |

검사: `check_core.py`(통계와 신호 해석), `check_ui.py`(화면 없이 실행하는 동작 검사), `check_tx.py`(메시지 송신). 모두 `tests/canmon/`에 있고 `python3 tests/test_checks.py canmon`으로 한 번에 실행합니다.

결정 사항(2026-11-06): 그래프 탭은 저장한 로그를 볼 때만 씁니다. 실시간 측정(2단계)에서는 Trace, 주기 통계, 버스 통계만 갱신합니다.

아직 없는 것: 버스 재생, EtherCAT 지연 비교(4단계), 신호 구성 저장, 패널 간 신호 이동.

## DBC 바꾸기

왼쪽 "채널과 DBC"에서 채널마다 DBC를 고릅니다.

- 목록에는 현재 DBC 폴더의 파일이 나옵니다. 맨 아래 "파일에서 선택…"으로 다른 위치의 DBC도 고를 수 있습니다.
- "DBC 폴더 변경…"으로 목록에 나오는 폴더를 바꿉니다. 기본은 저장소의 `data/dbc/`입니다(`CANMON_DBC_DIR`로 변경 가능).
- DBC 파일을 고친 뒤에는 "DBC 다시 읽기"를 누릅니다. 그려 둔 신호 중 새 DBC에도 있는 것은 유지됩니다.
- 읽을 수 없는 DBC는 오류를 표시하고 이전 DBC를 유지합니다.
- 설계 주기와 프레임 길이 검사는 `gen_dbc.py`가 넣는 `SubCodeCycles`, `SubCodeLengths` 속성을 씁니다. 이 속성이 없는 DBC는 `GenMsgCycleTime`만 사용합니다.

## 암호 없이 CAN 속도 설정하기 (측정용 노트북에서 한 번)

```bash
sudo src/qatools/tools/canmon/hw/install_can_access.sh          # 지금 사용자를 canmon 그룹에 등록
sudo src/qatools/tools/canmon/hw/install_can_access.sh kim lee  # 다른 사용자도 등록
```

`canmon` 그룹 사용자는 `/usr/local/sbin/canmon-setup` 하나만 암호 없이 관리자 권한으로 실행할 수 있습니다. 이 스크립트는 `can0` 같은 CAN 장치의 속도, 샘플 포인트, 수신 전용 여부만 바꾸고, 그 외 입력은 거부합니다. 한 번 로그아웃한 뒤부터 적용됩니다. 실제 장비에서 실행해 본 적은 없습니다.

UI에서도 설치할 수 있습니다: 메뉴 "도구 → CAN 설정 권한 설치…". 관리자 암호 창(pkexec)이 한 번 뜹니다. pkexec이 없는 PC에서는 터미널 명령을 복사해 주는 버튼을 씁니다.

## 하드웨어 설정

메뉴 "도구 → 하드웨어 설정…" 또는 도구 줄의 "하드웨어 설정…"에서 엽니다.

- 연결된 CAN 장치를 찾아 채널마다 프리셋(로컬 CAN 1 M / 5 M, D-CAN 125 k / 1 M), 속도, 샘플 포인트, DBC를 정합니다.
- "적용"을 누르면 장치에 설정한 뒤 실제로 잡힌 값을 다시 읽어 요청과 비교합니다. 다르면 무엇이 다른지 표시합니다.
- 측정은 수신 전용으로만 설정합니다. 송신 가능 모드는 결함 주입 단계에서 추가합니다.
- 구성을 프로필로 저장하고 불러올 수 있습니다. 화면에서 저장한 프로필은 이 PC의 사용자 설정에만 남습니다.
- 저장소의 `data/hw_profiles.json`에 있는 프로필(예: `FM26C`)은 모든 PC의 목록에 공용으로 나옵니다. 화면에서 지울 수 없고, DBC는 채널 이름(예: `HETC-L-TACT_ch0`)으로 적습니다.
- 분석기가 없으면 "CAN 장치를 찾지 못했습니다"가 표시됩니다. Windows와 WSL에서는 항상 이 상태입니다.
- 검사: `check_hw.py`. 가짜 장치 정보로 검사했고 실제 분석기로는 확인하지 못했습니다.

## 실시간 측정 (2단계)

1. "하드웨어 설정…"에서 채널, 속도, DBC를 정하고 "적용"을 누릅니다.
2. 도구 줄의 "● 측정 시작"을 누릅니다. 적용해 둔 채널을 수신 전용으로 읽습니다.
3. 측정 중에는 Trace와 주기 통계가 초당 10회 갱신됩니다. 그래프 탭은 꺼져 있습니다.
4. "■ 측정 정지"를 누르면 저장한 로그가 자동으로 열려 그래프까지 볼 수 있습니다. 150만 프레임이 넘으면 열지 물어봅니다.

- 로그는 `~/canmon_logs/can_날짜_시각.csv`에 저장됩니다. `qa canmon capture`와 같은 형식입니다.
- 주기 통계의 범위는 "측정 시작 또는 통계 초기화 이후"입니다. 정지 구간과 동작 구간을 나눠 보려면 "통계 초기화"를 누릅니다.
- 한계 배수를 바꾸면 그 뒤에 받은 프레임부터 적용됩니다.
- p99는 로그 눈금 히스토그램으로 구한 근삿값(위쪽 추정)입니다. 정확한 값은 로그를 열어 봅니다.
- 상태 줄에 채널별 부하, 프레임 수, 오류 프레임, 커널이 버린 프레임 수(수신 누락)를 표시합니다.
- 장비 없이 화면을 보려면 캡처 파일을 연 뒤 "도구 → 실시간 화면 미리 보기"를 누릅니다. 연 파일을 기록된 속도로 흘려보내는 것이고 측정이 아닙니다.
- 검사: `check_live.py`(실시간 통계가 오프라인 통계와 같은지, 로그가 원본과 같은지), `check_ui.py`의 실시간 부분. 실제 분석기 수신(`SocketSource`)은 확인하지 못했습니다.

## 메시지 송신 (3단계)

측정 중에 "메시지 송신" 탭에서 메시지를 버스에 보냅니다. CANoe의 송신 목록과 비슷합니다.

1. 측정을 멈춘 상태에서 "하드웨어 설정…"을 엽니다. 보낼 채널의 모드만 **송신 가능**으로 바꾸고 "적용"을 누릅니다. 이 설정은 저장되지 않아서, 설정 창을 다시 열면 수신 전용으로 돌아와 있습니다.
2. "● 측정 시작" 후 "메시지 송신" 탭에서 **송신 모드 켜기**를 누르고 확인합니다. 측정을 시작할 때마다 송신 모드는 꺼진 상태입니다.
3. 목록에 항목을 추가하고, 줄 맨 앞의 체크로 송신을 시작하거나 멈춥니다.

| 항목 | 내용 |
|---|---|
| + DBC 메시지 | 채널 DBC에서 메시지를 골라 신호 값을 표에서 입력합니다. SubCode 같은 다중화 신호를 바꾸면 그에 맞는 신호만 나옵니다. 주기는 DBC 설계 주기로 채워지고 바꿀 수 있습니다. 값이 범위를 벗어나면 보내지 않고 이유를 표시합니다. |
| + 직접 입력 | CAN ID, 29비트·FD·BRS, 데이터(16진수), 길이를 직접 정합니다. |
| + 부하 메시지 | DBC에 없는 더미 프레임(기본 0x1FFFFF00, 64바이트, 우선순위 낮음)을 **목표 부하율(%)** 로 보냅니다. 간격은 DBC의 속도와 프레임 길이로 계산합니다. |
| 주기 / 횟수 | 주기 0은 1회 송신입니다. 횟수 0은 멈출 때까지 보냅니다. 보내는 중에 값을 바꾸면 바로 반영됩니다. |
| 선택 1회 송신 | 선택한 항목을 한 번만 보냅니다. |

- **멈추기:** "전체 정지" 버튼이나 Esc를 누릅니다. 주기 송신은 자동 정지 시간(기본 60 초, 0이면 끔)이 지나면 저절로 멈춥니다. 측정을 멈추거나 프로그램을 닫아도 송신이 멈춥니다.
- **송신 가능 채널만:** 수신 전용 채널로는 보내지 않습니다. 송신 가능 채널은 보내지 않을 때도 버스에 ACK를 한다는 점에 주의합니다.
- **기록:** 보낸 프레임은 같은 로그에 `dir` 열 값 `tx`로 기록됩니다. Trace에는 채널이 "can1 Tx"처럼 파란색으로 표시되고, 상태 줄에는 송신 수가 나옵니다. 받은 프레임과 같은 방식으로 타임스탬프가 찍히도록 송신한 소켓의 에코를 기록합니다. 하드웨어 타임스탬프가 에코에도 붙는지는 분석기로 확인해야 합니다.
- **부하 표시:** 목록 아래에 보내는 중인 항목의 추가 부하 계산값을 채널별로 보여 줍니다. 50 %를 넘으면 빨간색입니다. 실제 부하는 상태 줄의 측정값으로 봅니다.
- **송신 목록:** 자동으로 저장됩니다. "목록 저장…"과 "목록 불러오기…"로 JSON 파일로 주고받을 수 있습니다.
- **송신 속도 한계:** 한 항목은 최대 초당 20,000 프레임입니다. 1 M / 5 M에서 64바이트 프레임 100 %가 초당 약 6,300 프레임입니다. 커널 송신 큐가 차면 잠깐 쉬었다가 다시 보내고, 그 횟수를 "큐 가득"으로 표시합니다.
- **장비 없이 써 보기:** 캡처 파일을 열고 "도구 → 실시간 화면 미리 보기"를 누르면 송신 탭을 쓸 수 있습니다. 보낸 프레임은 버스로 가지 않고 화면과 통계에만 Tx로 들어갑니다.
- **CAN ID 겹침:** 로봇 보드와 같은 ID를 보내면, 주기 통계에서 같은 메시지로 합쳐서 집계됩니다.
- 검사: `check_tx.py`(인코딩, 프레임 만들기, 송신 주기와 횟수·자동 정지·큐 가득·오류 처리, 로그 Tx 기록)와 `check_ui.py`의 송신 부분. 실제 분석기로 보내 본 적은 없습니다.
