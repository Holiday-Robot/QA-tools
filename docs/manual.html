FM26 CAN Monitor 사용 설명서

FM26 로봇의 CAN FD 버스를 기록하고, 메시지 주기와 신호를 분석하고, 시험용 메시지를 보내는 도구입니다. 화면마다 번호를 붙여 각 부분이 하는 일을 설명합니다.

오프라인 분석 · 완료 실시간 측정 · 완료 메시지 송신 · 완료 실제 분석기 확인 전

화면 이미지는 모두 가상 데이터(qa canmon sample로 만든 HETC-L-TACT 12초 기록)로 찍었습니다. 실시간 측정 화면은 이 파일을 실제 속도로 흘려보내 연출했고, 메시지 송신 화면은 can1을 송신 가능 채널로 가정했습니다. 실제 로봇이나 분석기에서 나온 값이 아닙니다. 이미지를 누르면 원래 크기로 볼 수 있습니다.

01처음 설치와 실행

명령은 저장소(QA-tools) 폴더에서 실행합니다. DBC는 저장소의 data/dbc에 있습니다.

실행하기

# QA Tools 창을 열고 왼쪽 목록에서 "CAN Monitor"를 고름
./qa

# CAN Monitor를 바로 열고 캡처 파일과 채널별 DBC를 지정
./qa gui canmon ltact.csv --map can0=HETC-L-TACT_ch0 --map can1=HETC-L-TACT_ch1

# QA Tools 창 없이 CAN Monitor만 실행
./qa canmon view

# 앱 메뉴에 "QA Tools" 바로가기와 로고 아이콘 등록 (사용자별, 관리자 권한 필요 없음)
./install_shortcut.sh

CAN Monitor는 QA Tools 창의 도구 중 하나입니다. 아래 화면 이미지는 CAN Monitor만 실행해 찍은 것이고, QA Tools 창에서는 같은 화면 왼쪽에 도구 목록이 하나 더 붙습니다.

  • 필요한 패키지: PyQt6, pyqtgraph, numpy, cantools입니다. 저장소 폴더에서 pip install -e ".[gui]"로 설치합니다.
  • 다른 폴더의 DBC를 쓸 때: 환경변수 CANMON_DBC_DIR로 DBC 폴더를 지정하거나, 프로그램 안에서 "DBC 폴더 변경…"을 누릅니다.
  • WSL: X11용 라이브러리가 없어 Wayland(WSLg)로 띄웁니다. qa 스크립트가 알아서 설정합니다. WSL과 Windows에서는 CAN 장치를 쓸 수 없어서 파일 분석만 됩니다.

측정용 노트북에서 한 번만 할 일

  1. Linux 설치. Ubuntu 같은 Linux를 설치합니다. PEAK PCAN-USB Pro FD 드라이버(peak_usb)는 커널에 들어 있습니다.
  2. 분석기 확인. 분석기를 꽂고 터미널에서 ip link를 실행해 can0, can1이 보이는지 확인합니다.
  3. CAN 설정 권한 설치. 메뉴 "도구 → CAN 설정 권한 설치…"를 엽니다(아래 화면). 설치한 뒤 한 번 로그아웃해야 적용되고, 그 뒤로는 속도를 바꿀 때 관리자 암호를 묻지 않습니다.
  4. 바로가기 등록. ./install_shortcut.sh로 앱 메뉴에 등록합니다.
  1. 현재 상태

    "설치되지 않았습니다", "설치는 되어 있지만 지금 사용자에게 권한이 없습니다", "설치되어 있습니다" 중 하나가 나옵니다. Linux가 아닌 PC에서는 "CAN 측정은 Linux에서만 됩니다"가 나오고 버튼이 꺼집니다.

  2. 등록할 사용자

    지금 로그인한 사용자가 기본값입니다. 여러 명은 쉼표나 띄어쓰기로 구분합니다. 영문 소문자, 숫자, _, -만 받습니다.

  3. 설치

    관리자 암호 창(pkexec)이 한 번 뜹니다. 등록된 사용자는 CAN 장치의 속도, 샘플 포인트, 수신 전용 여부만 바꾸는 스크립트 하나를 암호 없이 실행할 수 있게 됩니다.

  4. 터미널 명령 복사

    pkexec이 없는 PC에서는 이 버튼으로 sudo src/qatools/tools/canmon/hw/install_can_access.sh 사용자 명령을 복사해 터미널에서 실행합니다.

  5. 진행 기록

    설치 결과와 오류가 표시됩니다. 되돌릴 때는 sudo rm /etc/sudoers.d/canmon /usr/local/sbin/canmon-setup을 실행합니다.

02로봇에 연결하기 전

로봇이 정지한 상태에서 연결합니다. 처음 연결할 때는 하드웨어 설정에서 모든 채널을 수신 전용으로 둡니다. 수신 전용이면 분석기는 버스에 아무것도 보내지 않고 ACK도 하지 않습니다.

  • 변환 케이블: HETC 5핀 커넥터를 D-Sub 9핀에 연결합니다. D-Sub는 2번이 CAN-L, 3번이 GND, 7번이 CAN-H입니다. 5V와 ESTOP 핀은 연결하지 않습니다. HETC 쪽 핀 배열은 멀티미터로 먼저 확인합니다.
  • 종단저항: 분석기 쪽 종단저항은 꺼 둡니다. 이 프로그램에서는 바꿀 수 없으니 분석기 설정을 확인합니다.
  • 저항 확인: 연결 전후로 CAN-H와 CAN-L 사이가 약 60 Ω인지 확인합니다.

03메인 창

캡처 파일을 열면 보이는 첫 화면입니다. 위에는 도구 줄, 왼쪽에는 측정 설정, 가운데에는 분석 탭, 아래에는 상태 줄이 있습니다.

  1. 메뉴

    "파일"에서 열기와 끝내기, "도구"에서 하드웨어 설정, 측정 시작, 실시간 화면 미리 보기, CAN 설정 권한 설치를 고릅니다.

  2. 캡처 파일 열기

    qa canmon capture나 실시간 측정이 저장한 CSV를 엽니다. 마지막으로 연 폴더를 기억합니다.

  3. 하드웨어 설정

    분석기 채널의 속도, 샘플 포인트, 모드, DBC를 정합니다. 하드웨어 설정에서 자세히 설명합니다.

  4. 측정 시작 / 정지

    하드웨어 설정에서 적용한 채널로 실시간 측정을 시작합니다. 측정 중에는 "■ 측정 정지"로 바뀝니다.

  5. 재생과 배속

    연 파일을 시간 순서대로 재생합니다. 배속은 0.1배에서 5배까지 고릅니다. Trace의 최신 프레임과 그래프의 초록 세로선이 재생 시각을 따라갑니다.

  6. 시각 슬라이더

    끌어서 원하는 시각으로 갑니다. 오른쪽에 현재 시각과 전체 길이가 나옵니다.

  7. 모드 표시

    지금 상태를 색으로 보여 줍니다. 초록은 파일 재생, 파랑은 실시간 측정(수신 전용), 노랑은 미리 보기, 빨강은 송신 모드 켜짐입니다.

  8. 채널과 DBC

    파일의 채널마다 DBC를 고릅니다. 목록에는 DBC 폴더의 파일이 나오고, "파일에서 선택…"으로 다른 위치의 DBC도 고를 수 있습니다. DBC를 고친 뒤에는 "DBC 다시 읽기"를 누릅니다. 마지막 선택은 저장됩니다.

  9. DBC 탐색

    DBC에 있는 메시지와 신호 목록입니다. 신호 이름으로 검색하고, 메시지를 펼쳐 신호를 체크하면 그래프에 추가됩니다.

  10. 화면 탭

    Trace, 주기 통계, 그래프를 오갑니다.

  11. 상태 줄

    채널별 버스 부하, 초당 프레임 수, 오류 프레임 수, 타임스탬프 종류(하드웨어 / 소프트웨어), 기록 길이와 프레임 수를 보여 줍니다.

타임스탬프가 "소프트웨어"로 나오면 USB와 OS 스케줄링 지연이 섞인 시각입니다. 1 ms 미만의 간격 차이는 믿지 않습니다.

04Trace

받은 프레임을 그대로 봅니다. 메시지별 최신 프레임을 보는 "ID별 고정"과 모든 프레임을 순서대로 보는 "시간순"이 있습니다.

ID별 고정

  1. 표시 방식

    "ID별 고정"과 "시간순" 중에서 고릅니다.

  2. 거르기

    채널, CAN ID, 메시지 이름, 형식(SubCode 이름)의 일부를 입력하면 맞는 줄만 남습니다. 대소문자는 구분하지 않습니다. tx를 입력하면 이 PC가 보낸 메시지만 남습니다.

  3. 보이는 메시지 수

    거르고 남은 줄 수입니다.

  4. 시각

    재생 시각 이전에 받은 그 메시지의 마지막 프레임 시각(초)입니다. 파일의 첫 프레임이 0입니다.

  5. 주기

    그 프레임과 직전 같은 메시지 사이의 간격(ms)입니다. STATUS·CTRL은 SubCode별로, 촉각 메시지는 포인트별로 따로 셉니다.

  6. 신호 값

    줄 앞의 화살표를 누르면 DBC로 해석한 신호 값이 단위와 함께 나옵니다. DBC에 없는 ID는 주황색 "(DBC에 없음)"으로 표시됩니다.

시간순

  1. 시간순

    파일의 모든 프레임을 시각 순서대로 보여 줍니다. 수십만 프레임도 스크롤할 수 있습니다.

  2. 거르기

    ID별 고정과 같은 방식입니다. 오른쪽에 남은 프레임 수가 나옵니다.

  3. 프레임 목록

    시각, 채널, CAN ID, 메시지, 형식, 길이, 데이터(16진수)입니다. 이 PC가 보낸 프레임은 채널이 "can1 Tx"처럼 파란색으로 나옵니다.

  4. 선택한 프레임

    시각, 채널, 길이, 전체 데이터와 DBC로 해석한 모든 신호 값을 보여 줍니다.

05주기 통계

메시지마다 수신 간격을 재고 DBC의 설계 주기와 비교합니다. 엔코더나 통신이 끊긴 곳을 찾는 데 씁니다.

  1. 통계 범위

    "측정 전체", "커서 A–B 구간", 그래프에서 저장한 구간 중에서 고릅니다. 정지 구간과 동작 구간을 나눠 볼 때 씁니다.

  2. 한계

    간격이 "설계 주기 × 이 값"을 넘으면 한계 초과로 셉니다. 기본은 5배입니다.

  3. 한계 초과 건수

    한계를 넘은 메시지 수입니다. 없으면 초록, 있으면 빨강입니다.

  4. CSV 내보내기

    지금 표를 CSV로 저장합니다. 엑셀에서 한글이 깨지지 않게 저장합니다.

  5. 한계를 넘은 메시지

    빨간 배경으로 강조합니다. 열 제목을 누르면 정렬됩니다.

  6. 통계 열

    수신 수, 평균·최소·최대 간격, p99, 설계 주기(ms)입니다. 오른쪽에 최대/설계 비율과 한계 초과 횟수가 이어집니다. 설계 주기는 DBC의 SubCodeCycles 속성이나 GenMsgCycleTime에서 읽습니다.

  7. 간격 분포

    선택한 메시지의 수신 간격 히스토그램입니다(프레임 수는 로그 눈금). 빨간 점선이 한계입니다.

  8. 세부 값

    최대 간격, 그 간격이 끝난 시각, 한계 초과 횟수, p99, 프레임 길이별 수를 보여 줍니다.

  9. 그래프로 보기

    "그래프에 간격 표시"는 이 메시지의 수신 간격을 그래프 아래 칸에 그립니다. "최대 간격 위치로 이동"은 그래프를 열고 최대 간격이 생긴 곳을 확대합니다.

06그래프

신호 값, 상태 신호, 수신 간격을 한 시간축에 겹쳐 봅니다. 저장한 로그를 볼 때만 씁니다. 측정 중에는 꺼져 있습니다.

  1. 샘플 점, 선 모양

    확대해서 점 사이가 충분히 벌어지면 받은 프레임마다 점을 찍습니다. 선 모양은 직선과 계단 중에서 고릅니다.

  2. 전체 보기

    기록 전체가 보이도록 축을 되돌립니다.

  3. CSV · 이미지 저장

    그린 신호를 CSV로 내보내거나 그래프를 이미지로 저장합니다.

  4. 신호 값

    숫자 신호를 그립니다. 점선 A·B가 커서이고, 끌어서 옮깁니다. 두 커서 사이는 옅은 파랑으로 칠해집니다.

  5. 상태 신호

    RUN, ERROR 같은 이름이 있는 신호는 별도 칸에 이름으로 그립니다.

  6. 수신 간격

    주기 통계에서 고른 메시지의 프레임 간격(ms)입니다. 빨간 점선이 한계, 빨간 점이 한계를 넘은 곳입니다.

  7. 점 정보

    그래프의 점에 마우스를 올리면 신호 이름, 시각, 값, 직전 프레임과의 간격이 나옵니다.

  8. 신호 표

    신호마다 커서 A와 B의 값, 차이(B − A), 최소·평균·최대입니다.

  9. 통계 범위, 신호 빼기

    표의 최소·평균·최대를 화면 범위, 커서 A–B 구간, 측정 전체 중 어디서 계산할지 고릅니다. 표에서 신호를 고르고 "선택한 신호 빼기"를 누르면 그래프에서 빠집니다.

  10. 구간 저장

    이름을 쓰고 "커서 구간 저장"을 누르면 지금 A–B 구간이 저장됩니다. 목록을 누르면 커서가 그 구간으로 옮겨지고, 주기 통계의 범위에서도 고를 수 있습니다.

  11. 커서 시각

    커서 A, B의 시각과 둘 사이 간격 Δt(ms)입니다.

마우스 조작

07하드웨어 설정

"도구 → 하드웨어 설정…" 또는 도구 줄의 "하드웨어 설정"으로 엽니다. 측정 중에는 열 수 없습니다.

  1. 장치 다시 찾기

    분석기를 꽂은 뒤 누르면 CAN 장치 목록을 다시 읽습니다. 장치가 없으면 "CAN 장치를 찾지 못했습니다"가 나옵니다.

  2. 프로필

    지금 표의 구성을 이름을 붙여 저장하고 불러옵니다. 예를 들어 "왼팔 촉각 로컬 CAN"처럼 저장해 둡니다.

  3. 권한 설치

    CAN 설정 권한 설치 창을 엽니다.

  4. 사용, 채널, 장치

    체크한 채널만 설정하고 측정합니다. 장치 칸에는 USB 제품명, 일련번호, 분석기 채널 번호가 나옵니다.

  5. 프리셋과 속도

    "로컬 CAN (1 M / 5 M)"은 87.5 % / 62.5 % 샘플 포인트, "D-CAN (125 k / 1 M)"은 드라이버 자동입니다. 값을 직접 바꾸면 프리셋이 "직접 입력"으로 바뀝니다. 샘플 포인트 0은 "자동"입니다.

  6. 모드

    수신 전용이 기본입니다. 메시지를 보낼 채널만 송신 가능(빨간 글씨)으로 바꿉니다. 이 선택은 저장되지 않아서, 창을 다시 열면 수신 전용으로 돌아와 있습니다.

  7. DBC

    채널마다 실시간 측정에 쓸 DBC를 고릅니다.

  8. 현재 상태

    장치에서 다시 읽은 실제 값입니다. 켜짐/꺼짐, 버스 상태(ERROR-ACTIVE, ERROR-PASSIVE, BUS-OFF), 속도, 모드, 오류 카운터를 보여 줍니다.

  9. 적용 결과

    채널마다 ✔ 또는 ✖입니다. 적용한 뒤 장치 값을 다시 읽어 요청과 다르면 무엇이 다른지 적습니다.

  10. 적용

    체크한 채널에 설정을 보내고 다시 읽어 확인합니다. 저장된 설정은 다음 측정에 쓰입니다.

송신 가능 채널은 보내지 않을 때도 버스에 참여합니다. 다른 노드의 프레임에 ACK를 하고, 속도나 샘플 포인트가 틀리면 오류 프레임을 낼 수 있습니다. 로봇 버스에서는 송신이 필요한 채널만, 필요한 동안만 송신 가능으로 둡니다.

08실시간 측정

  1. 하드웨어 설정에서 적용. 채널, 속도, DBC를 정하고 "적용"을 누릅니다.
  2. "● 측정 시작". 적용한 채널을 읽기 시작하고, 로그를 ~/canmon_logs/can_날짜_시각.csv에 저장합니다.
  3. 보기. Trace, 주기 통계, 메시지 송신 탭이 초당 10회 갱신됩니다. 그래프 탭은 측정 중에는 꺼져 있습니다.
  4. "■ 측정 정지". 저장한 로그가 자동으로 열려 그래프까지 볼 수 있습니다. 150만 프레임이 넘으면 열지 먼저 묻습니다.
  1. 측정 정지

    측정을 끝내고 로그를 엽니다. 측정 중에는 파일 열기, 재생, 하드웨어 설정, 왼쪽 패널이 잠깁니다.

  2. 측정 시간과 프레임 수

    측정을 시작한 뒤 지난 시간과 받은 전체 프레임 수입니다.

  3. 실시간 측정 표시

    파랑은 "실시간 측정 · 수신 전용"입니다. 송신 모드를 켜면 빨강으로 바뀝니다.

  4. 측정 중 화면

    Trace, 주기 통계, 메시지 송신을 씁니다. 그래프는 측정 후에 저장한 로그로 봅니다.

  5. 메시지별 최신 프레임

    새 메시지가 들어오면 줄이 추가됩니다. 펼치면 최신 신호 값이 나옵니다.

  6. 상태 줄

    채널별 부하와 초당 프레임 수(최근 1초), 오류 프레임, 수신 누락(커널이 버린 프레임), 이 PC의 송신 수, 타임스탬프 종류, 로그 파일 위치입니다.

  1. 통계 범위

    측정 시작 또는 마지막 초기화 이후의 프레임으로 계산합니다. 괄호 안은 그동안 지난 시간입니다.

  2. 한계

    바꾸면 그 뒤에 받은 프레임부터 적용됩니다.

  3. 한계 초과 건수

    한계를 넘은 메시지 수입니다.

  4. 통계 초기화

    통계를 지금부터 다시 셉니다. 로그 저장은 계속됩니다. 로봇을 정지에서 동작으로 바꿀 때 누르면 구간을 나눠 볼 수 있습니다.

  5. CSV 내보내기

    지금까지의 통계를 저장합니다.

  6. 메시지별 통계

    오프라인 주기 통계와 같은 열입니다. 실시간에서는 p99를 히스토그램으로 추정한 근삿값(위쪽 값)으로 보여 줍니다. 정확한 값은 측정 후 로그에서 봅니다.

  7. 간격 분포

    선택한 메시지의 수신 간격 분포입니다.

장비 없이 화면 미리 보기: 캡처 파일을 연 뒤 "도구 → 실시간 화면 미리 보기"를 누르면 그 파일을 기록된 속도로 흘려보냅니다. 측정이 아니라서 로그를 저장하지 않고, 모드 표시가 노랑입니다. 메시지 송신 탭도 써 볼 수 있으며 보낸 프레임은 버스로 가지 않습니다.

09메시지 송신

측정 중에 시험용 메시지를 보냅니다. DBC 메시지를 신호 값과 주기로 보내거나, 직접 만든 프레임을 보내거나, 더미 프레임으로 버스 부하를 올립니다.

로봇 버스에 프레임을 보내는 기능입니다. 로봇이 움직이는 중이면 먼저 멈춥니다. 언제든 Esc로 모든 송신을 멈출 수 있습니다.

보내기 전에

  1. 송신 가능 채널 만들기. 측정을 멈춘 상태에서 하드웨어 설정을 열고, 보낼 채널의 모드만 "송신 가능"으로 바꾼 뒤 "적용"을 누릅니다.
  2. 측정 시작. 보낸 프레임도 로그에 함께 기록되도록, 송신은 측정 중에만 할 수 있습니다.
  3. 송신 모드 켜기. "메시지 송신" 탭에서 "송신 모드 켜기"를 누르고 확인 창에서 "예"를 누릅니다. 측정을 시작할 때마다 송신 모드는 꺼져 있습니다.
  1. 송신 모드 켜기 / 끄기

    켜야만 보낼 수 있습니다. 끄면 보내던 것이 모두 멈춥니다. 측정을 멈추거나 프로그램을 닫아도 꺼집니다.

  2. 송신 모드 상태

    꺼져 있으면 초록 "분석기는 아무것도 보내지 않습니다", 켜져 있으면 빨강으로 보낼 수 있는 채널이 나옵니다.

  3. 자동 정지

    주기 송신은 시작하고 이 시간이 지나면 저절로 멈춥니다. 기본 60초이고, 0("끔")이면 멈추지 않습니다.

  4. 전체 정지 (Esc)

    보내는 중인 모든 항목을 멈춥니다. 몇 개가 보내는 중인지 버튼에 표시됩니다.

  5. 목록 저장 · 불러오기

    송신 목록은 자동으로 저장되어 다음에도 남습니다. 시험 절차별로 JSON 파일로 저장해 두고 불러올 수 있습니다.

  6. 항목 추가

    "+ DBC 메시지", "+ 직접 입력", "+ 부하 메시지" 중에서 고릅니다. 아래 표에 종류별 차이를 정리했습니다.

  7. 복제 · 삭제

    선택한 항목을 복사하거나 지웁니다. 보내는 중인 항목을 지우면 멈춥니다.

  8. 선택 1회 송신

    선택한 항목을 주기와 상관없이 한 번만 보냅니다.

  9. 송신 체크

    체크하면 보내기 시작하고, 해제하면 멈춥니다. 주기가 "1회"인 항목은 체크하면 한 번 보내고 저절로 해제됩니다. 횟수를 다 채우거나 자동 정지되어도 해제됩니다.

  10. 보낸 수와 상태

    "보내는 중", "1회 송신함", "횟수 완료", "자동 정지", "정지"가 나옵니다. 송신 큐가 차서 잠시 쉰 횟수("큐 가득")와 늦어서 건너뛴 횟수도 붙습니다. 값이 잘못되면 빨간 글씨로 이유가 나옵니다.

  11. 추가 부하 계산값

    보내는 중인 주기 항목이 채널마다 더하는 부하의 합입니다. 50 %가 넘으면 빨강입니다. 실제 부하는 상태 줄의 측정값으로 확인합니다.

  12. 선택한 항목 편집

    채널, 메시지, 주기, 횟수, 메모를 바꿉니다. 보내는 중에 바꿔도 바로 반영되고, 보낸 수와 자동 정지 시간은 이어집니다.

  13. 신호 값

    DBC 메시지의 신호를 입력합니다. 이름이 있는 값(예: ESTOP)은 목록에서 고릅니다. SubCode 같은 다중화 신호를 바꾸면 그에 맞는 신호만 다시 나오고, 주기도 그 SubCode의 설계 주기로 바뀝니다. 비워 둔 신호는 DBC 초기값이나 0을 씁니다.

  14. 미리 보기

    실제로 보낼 CAN ID, 길이, FD/BRS, 데이터 바이트와 주기에 따른 초당 프레임 수, 추가 부하입니다. 값이 범위를 벗어나면 빨간 글씨로 이유가 나오고 보내지 않습니다.

항목 종류

종류정하는 것쓰임
DBC 메시지채널 DBC의 메시지, 신호 값, 주기, 횟수QUIET, EVENT, CTRL처럼 DBC에 있는 메시지를 정확한 값으로 보낼 때
직접 입력CAN ID(16진수), 29비트·FD·BRS, 데이터 바이트, 길이, 주기, 횟수DBC에 없는 프레임, 잘못된 길이 같은 비정상 프레임
부하 메시지더미 CAN ID(기본 0x1FFFFF00), 길이(기본 64), 목표 부하 %버스 부하를 원하는 만큼 올려 다른 메시지의 주기가 어떻게 되는지 볼 때
  1. 더미 CAN ID와 형식

    29비트 ID 중 우선순위가 가장 낮은 쪽을 기본으로 씁니다. 중재에서 로봇 메시지에 밀리도록 하기 위해서입니다.

  2. 길이

    길수록 프레임 하나가 버스를 오래 씁니다.

  3. 목표 부하

    원하는 추가 부하(%)입니다. 송신 간격은 DBC 속도(Baudrate, BaudRateCANFD)와 길이로 계산합니다.

  4. 계산 결과

    송신 간격, 초당 프레임 수, 추가 부하를 보여 줍니다.

  1. CAN ID

    16진수로 입력합니다(0x는 붙여도 되고 빼도 됩니다).

  2. 형식

    29비트 확장 ID, CAN FD, BRS(데이터 구간 고속)를 정합니다. 8바이트가 넘으면 FD로 보냅니다.

  3. 데이터

    01 02 0A처럼 바이트를 띄어 씁니다. 길이를 정하면 모자란 만큼 0으로 채우고 넘는 만큼 자릅니다. FD는 유효한 길이(12, 16, 20, 24, 32, 48, 64)로 맞춥니다.

  4. 주기와 횟수

    주기 0은 1회, 횟수 0은 멈출 때까지입니다.

송신 한계와 기록

  • 속도: 한 항목은 초당 최대 20,000 프레임입니다. 1 M / 5 M에서 64바이트 프레임으로 부하 100 %가 초당 약 6,300 프레임입니다.
  • 송신 큐가 찰 때: 1 ms 쉬었다가 다시 보내고 그 횟수를 "큐 가득"으로 셉니다. 버스가 포화되면 늘어납니다.
  • 기록: 보낸 프레임은 같은 로그에 dir 열 값 tx로 기록됩니다. 받은 프레임과 같은 방식으로 시각이 찍히도록, 분석기가 돌려준 송신 확인(에코)을 기록합니다.
  • ID가 겹칠 때: 로봇 보드와 같은 ID를 보내면 주기 통계에서 두 프레임이 한 메시지로 합쳐집니다. 주기 분석을 할 메시지와 겹치지 않는 ID를 씁니다.

11로그 파일과 명령줄 도구

로그 형식

실시간 측정과 qa canmon capture가 같은 CSV 형식으로 저장합니다. 실시간 측정 로그에는 dir 열이 하나 더 있습니다.

열내용
t_hw하드웨어 타임스탬프(초). 분석기가 주지 않으면 비어 있습니다.
t_swPC가 받은 시각(초)
iface채널 이름(can0 등)
can_idCAN ID(16진수)
ext, fd, brs, esi, err29비트, CAN FD, BRS, ESI, 오류 프레임 여부(0/1)
len, data데이터 길이와 16진수 데이터
dir이 PC가 보낸 프레임이면 tx, 받은 프레임이면 비어 있음

화면 없이 캡처하고 보고서 만들기

# 채널 설정 (수신 전용). 로컬 CAN은 local, D-CAN은 dcan
sudo ./qa canmon setup can0 local
sudo ./qa canmon setup can1 local

# 60초 캡처 (Ctrl+C로 먼저 끝낼 수 있음)
./qa canmon capture can0 can1 -o ltact.csv --seconds 60

# 주기 분석 보고서 (Markdown). --limit으로 한계 배수 변경
./qa canmon analyze ltact.csv --map can0=HETC-L-TACT_ch0 --map can1=HETC-L-TACT_ch1 -o ltact.md

# 한 메시지의 신호를 CSV로 내보내기 (예: 손바닥 HTAC 엔코더)
./qa canmon analyze ltact.csv --map can1=HETC-L-TACT_ch1 --decode 0xF13382 -o enc51.csv

12문제 해결

증상확인할 것
"CAN 장치를 찾지 못했습니다"분석기가 꽂혀 있는지, ip link에 can0이 보이는지 확인합니다. Windows와 WSL에서는 항상 이렇게 나옵니다.
적용하면 "설정 실패 … password is required"CAN 설정 권한을 설치하지 않았거나, 설치 후 로그아웃하지 않았습니다.
"적용했지만 요청과 다릅니다"드라이버가 그 속도나 샘플 포인트를 정확히 맞추지 못한 것입니다. 메시지에 나온 실제 값을 보고 샘플 포인트를 조정합니다.
"측정할 채널이 없습니다"하드웨어 설정에서 채널을 체크하고 "적용"을 눌렀는지 확인합니다. 켜져 있는 채널만 측정합니다.
"보낼 수 있는 채널이 없습니다"측정 중인 채널이 모두 수신 전용입니다. 측정을 멈추고 하드웨어 설정에서 그 채널만 송신 가능으로 적용합니다.
상태 줄에 "수신 누락"이 늘어남PC가 프레임을 다 읽지 못해 커널이 버리고 있습니다. 다른 프로그램을 닫고, 그래도 늘면 그 구간의 통계는 믿지 않습니다.
타임스탬프가 "소프트웨어"분석기가 하드웨어 시각을 주지 않습니다. 1 ms 미만의 간격 차이는 해석하지 않습니다.
메시지 이름이 "(DBC에 없음)"채널에 맞는 DBC를 골랐는지 확인합니다. DBC를 고쳤으면 "DBC 다시 읽기"를 누릅니다.
한글이 네모로 나옴한글 글꼴이 없는 PC입니다. 프로그램이 Windows의 맑은 고딕을 찾아 씁니다. Linux 노트북이면 fonts-noto-cjk를 설치합니다.
작업 표시줄 아이콘이 기본 아이콘./install_shortcut.sh를 실행하고 창을 다시 엽니다.
